Use together with `telemetry_workbench_v11.html` + `telemetry_workbench_v11.js` (the baseline; keep both in one folder). Optional: `audit_harness_v11.js` (`node audit_harness_v11.js telemetry_workbench_v11.html`), `sensors_example.json`. ## 0. v11 changes (override older text where they differ)
- **JS moved** to `telemetry_workbench_v11.js`; the HTML keeps the two JSON config blocks (units, embedded calibration). Harness loads the file named in `<script src>`.
- **Validity status `insufficient`** (new, shown with an "…" badge): fewer than `ANALYSIS_THRESHOLDS.minSamples` = 64 uniform samples. Derived in code (`analysisMinSamples`, `ANALYSIS_DESIGN`) from the smallest effect each check must resolve: autocorrelation 64 (band 2/sqrt(n) <= rho/2, rho 0.5 = the AR(1) value at the n_eff/n = 0.30 warn level), CUSUM step 35 (Q = delta*sqrt(n)/4 >= 1.36 + 0.84 for delta = 1.5 sigma), Allan 64 (5 octaves), Welch 64 (4 segments x 16). It is a SAMPLE count, valid for any rate (6.4 s at 10 Hz, 0.8 s at 80 Hz; the readout says so). A found problem (gaps/duplicates/range) outranks it; it never counts as a pass. Not covered: settling time after a load change (a time, not a count).
- **Fixes:** paused Y axis (damping advanced once per rendered frame; now keeps rendering until both edges settle, `state.yBusy`); validity lists could not be opened (readouts were rewritten every frame): `setHTML` writes only on change, open state is remembered per key (`state.detailsOpen`), log rows now contain the expandable list and clicks inside it no longer jump.
- **Navigation panel** hidden by default; Settings > Layout toggles it (Selection analysis gets the width). **Track Live** switches on automatically when the view reaches the far right (`autoTrackIfAtEnd`, not while an interval is selected); the Track Live button shows the state (aria-pressed / primary).
- **Multi-sensor.** `state` is a pointer to the state of the SHOWN sensor (`createSensorState`, `sensors` Map, `activeSensor`); `RATE_HZ`, `PERIOD_MS`, `CALIBRATION`, `calibration` mirror that sensor. Per sensor: ring buffer, tares, calibrations, logs, selection, view, estimator/unit settings, rate, pause flag. Only the shown sensor is processed; others store time + raw counts (`appendRawOnly`, derived arrays not even allocated until first shown) and catch up in `prepareStateForDisplay` (calibrate the stored samples, `rebuildDerived`, `rebuildEMA`).
- **Ingest** `ingestSample(sensor, raw, timeMs)`: paused sensor discards (`state.dropped`); non-monotonic device time is rejected (`state.rejected`); time gap cancels a running measurement.
- **Header:** sensor drop-down (test signal always first), test-signal select beside it (only while the test sensor is shown), Pause (shown sensor), Pause all / Resume all. "+100k" button only for the test sensor.
- **Server (prepared, untested against a real server):** `SENSOR_LIST_URL` (null now), `applySensorList` / `loadSensorList` (Settings > Reload sensor list). Reload keeps data; changed names/URLs are updated; sensors missing from the list are marked "not in list", stop receiving data, keep their history. `syncConnections`: one EventSource per distinct URL, open only while a listed, unpaused sensor uses it. ASSUMED SSE message format (change in `handleSseMessage`): JSON sample, array, or {"samples":[...]} with {"id","t" (device ms),"raw"}; first t of a sensor = time origin.
- **Decisions to confirm:** server sensors start in RAW unit (no calibration of their own yet; the demo calibration is not applied to them silently); the embedded demo calibration is the initial one for all; calibration import acts on the shown sensor; `rateHz` is read from the list only when a sensor is created; per-sensor counter (Uint32) not stored yet; navigation-panel visibility is not persisted across reloads.
- **Not verified (needs browser/server):** header layout with the new controls, option-icon rendering, sensor switching with real uPlot (chart destroy/create), SSE behaviour (reconnect, shared URL), memory with many sensors at 1M samples, the Y-settle fix and the details fix visually. Harness: 160 checks pass (v10's 126 + V13-V17 multi-sensor/insufficient/auto-live/details/Y).

## 2. Architecture (what exists in v10; v9 text unchanged unless marked v10)
- **Data:** typed arrays per sample: time (Float64), raw counts (Int32), `massMg`, rawMA, rawSD, massMA, massSD (about 52 B/sample). The canonical mass unit is **mg**; unit selection is presentation only. Ring capacity is selectable (10k to 1M or unlimited, growing in 100k steps).
- **Ingest:** `appendSample(raw)` calibrates per sample (`calibrateAbsolute`: piecewise-linear interpolation, linear extrapolation, flagged `outOfRange`), subtracts the tare in force, and updates rolling sums in O(1). Sums are **shifted by a reference** (`rawRef`, `massRef`) and exactly rebuilt every 8,192 samples (`refreshRollingSums`). `rebuildDerived()` recomputes the derived arrays after a window change.
- **Tare:** an **event** (`state.tareEvents`: `effectiveFromTime`, `tareMassMg`, raw snapshot, out-of-range count). Net = absolute mass minus the tare in force **at that sample's time**. The tare is the mean of f(raw_i) over the tare window. Statistics windows never cross a tare.
- **Calibration:** `CALIBRATION` (active, switchable), `EMBEDDED_CALIBRATION`, `state.calibrations` (history with `effectiveFromTime`), `calibrationAt(t)`. Import validates structure and monotonicity (`validateCalibrationConfig`). Fingerprint = SHA-256 of canonical (sorted-key) JSON, FNV fallback on `file://` (labelled). **Stored masses are never recomputed.** A calibration change starts a new epoch: the tare is reset, a running measurement is aborted, and a "Cal" marker is drawn.
- **Estimators** (`estimate()`): mean, median, trimmed mean, global MAD filter + mean (Hampel-style, MAD=0 fallback), EMA. Each returns a **matching σ**: SD, 1.4826×MAD, SD of retained samples (biased low), SD of kept samples (biased low), exponentially weighted SD. **v10 adds** `hampelLocal` (true sliding Hampel identifier, k and n-sigma settable, flagged samples excluded, scale floor = max(1/3 of the first-difference noise level, one quantisation step)) and `emaNorm` (seed-normalised exponential weights; weighted mean and SD; Kish effective sample size reported). The old `hampel` (global MAD gate) and `ema` (seeded) stay as separate options. One **window** setting drives the chart curve, spread, panel and Auto-Tare. Robust estimators use at most the newest 4,096 samples (`hampelLocal` selections: newest 200,000 contiguous samples, disclosed).
- **Chart:** `buildEstimatorCurve()` gives centre and ±1σ for the selected estimator. Mean uses the stored rolling values, EMA runs sample by sample with a 7τ warm-up, and the sort-based estimators use a sparse aligned grid plus cache and interpolation when many samples are visible.
- **Selection and Measurement:** `calculateSelection(first,end,settings)` returns original (as recorded) and current (re-calibrated, latest tare) results, with `crossesTare`, `crossesCalibration` and `calibrationChanged` flags. `startMeasurement()` collects the next N samples (settings captured at start), reuses `calculateSelection`, highlights the samples (amber) and logs an entry. Tare, calibration change, buffer shrink or a sampling gap cancel it.
- **Validity analysis (v10):** pure functions (`analyzeSeries`, `analysisGaps`, `analysisAutocorrCheck`, `analysisAllanCheck`, `analysisStepCheck`, `analysisSpectrumCheck`, `analysisSegments`, `analysisFFT`, thresholds in `ANALYSIS_THRESHOLDS`) in a marked block of the script. `analyzeInterval(first,end)` feeds them raw counts, timestamps and the out-of-range count; the result `{status, checks:[{id,value,valueText,threshold,verdict,detail}], segments, analyzedN, note}` is stored with every Selection and Measurement, shown in Selection analysis (details list), the Measurement note, the log row badge and the event tooltip. Verdicts: ok / suspect / invalid / n/a (n/a never counts as a pass; an interval under 32 uniform samples is `suspect`). Checks run on the longest uniform segment, newest 40,000 samples. `counters` (ESP32) is already supported by `analysisGaps`.
- **Navigator (v10):** min/max buckets of 2^L samples aligned to absolute sample numbers, complete buckets cached (`state.miniCache`), about 4 points per pixel. Main chart and navigator are created independently (`createMainChart`, `createMiniChart`, `recreateMainChart` on estimator change).
- **Y axis (v10):** `autoYStep` = per-edge dead-band with latch (tight 0.5 x pad, loose 0.12 x span, release 0.02 x span); `snapY` gives one undamped step after the tab was hidden (visibilitychange, or a render gap > 2 s) and on the first frame.
- **Highlights and events (v10):** `drawSpans` is shared by both charts (teal selection, amber measurement, blue clicked log entry, white dashed hover; tare/calibration as lines; thin top lane for every logged span). `hitTestEvents` + `describeEventHTML` give the hover tooltip in both charts; hovering a log row, lane or marker lights up both graphs; clicking a row pins it.
- **Simulator (v10):** Settings has a test-signal select (wandering default, quiet, 50 Hz hum (aliases to 30 Hz), occasional weight steps) so the validity checks can be exercised in the browser.
- **Simulator:** `tick()` generates samples from wall-clock time (catch-up of at most 400 samples, then a timestamp gap). A real device replaces this.
- **UI layout:** header (status, Pause, +100k test samples, theme, Settings with Calibration); four metric columns (mass + spread with the settings panel under both, tare + tare options, measurement); full-width main chart and navigator (click or drag moves the main view); a control bar below the navigator (Track Live, Select interval, Export CSV, Buffer limit); then Display options / Selection analysis / Navigation, then the log.
- **CSV:** per row the recorded calibration revision and an out-of-range flag. `moving_average_net_mg` and `spread_sigma_mg` stay the arithmetic mean and SD whatever estimator is selected.

## 3. Decisions to keep
- Calibrate each sample first, then average (the mean of f(raw)), not f(mean raw). The choice is purpose-dependent and nearly identical for near-linear cells; do not call it "critical".
- A selection's "original" value uses the calibration and tare recorded at the time. "Current" re-applies the active calibration and latest tare. Both are shown, with warnings.
- Any selection, measurement or window crossing a tare or calibration boundary is flagged or prevented.
- Escape every text from calibration files before `innerHTML` (`esc()`).
- The EMA is seeded with the first sample (seed weight e^(-T/τ)); this is disclosed in the readouts.

## 4. Planned features (in order)
1. **Analysis milestone: DONE in v10** (see section 2). Still open: tune the thresholds on real ESP32 data; optionally show an Allan plot; the wizard should reuse `analyzeSeries`.
2. **Calibration creator wizard**, after analysis: first a simple version, then a professional one (reference weights, observations, anchors, validation metadata). It reuses the same analysis functions and writes the existing calibration JSON schema (`schemaVersion` 1).
3. **ESP32 integration.** The device supplies a **timestamp** and a **per-sample counter**. Timestamps are authoritative; the counter detects dropped or duplicated frames (a gap splits an interval into segments, because autocorrelation and Allan deviation need uniform sampling). Store the counter in a `Uint32Array` (+4 B/sample). Measurement should record the achieved rate and duration, not only N. `appendSample` must accept a device time and reject non-monotonic times, because the binary searches assume sorted time.

## 5b. v10 decisions and caveats
- Analysis uses RAW counts so that tare/calibration changes cannot create or hide a step; all checks are scale-free. Thresholds are rules of thumb, not calibrated to any hardware; "no problem detected" is not an uncertainty.
- The CUSUM step statistic estimates its noise level from the residuals of the fitted two-level step; if those residuals are still strongly correlated the step check reports n/a and defers to the autocorrelation and Allan checks. Expected false-alarm rate on white noise is about 5 % `suspect` (by construction of the 1.36 critical value).
- Spectrum lines below 1 Hz are ignored (drift / air flow); lines above 40 Hz alias (reported as apparent frequency).
- `hampelLocal` excludes flagged samples instead of replacing them by the local median (replacement would insert synthetic values).
- Curve of `emaNorm` starts its recursion 7 tau before the view (tail weight < 0.1 %), like the old EMA curve.
- Product decision to confirm: an interval shorter than 32 uniform samples gets status `suspect` ("too short to validate") rather than `ok`.

## 7. Working method that worked
- **Audit first, then patch.** Audit the current code, record findings with severity and status, test, then change incrementally.
- **Python patch scripts** with asserted unique replacements (`rep`/`region`), then `node --check` on the extracted script.
- **Headless harness:** it loads the real inline script into a Node `vm` with a DOM stub, so it tests logic only (not rendering). The stub invents any element id, so also cross-check `$('id')` references against the HTML ids statically.
- Tests exist for calibration, units, tare epochs, rolling statistics, estimators and sigma, selection, measurement, import validation, pacing, CSV provenance, curve and layout contracts. Run `node audit_harness_v10.js telemetry_workbench_v10.html`; all 126 checks passed at v10 (the v9 tests plus V1-V12: analysis on synthetic signals, FFT vs DFT, AR(1) n_eff, Allan slope, Hampel, EMA-normalised vs brute-force weights, navigator stability, Y dead-band, hit-testing, static id cross-check).
