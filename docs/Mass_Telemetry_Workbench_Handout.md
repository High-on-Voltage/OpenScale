## 2. Decisions I took that you should check
1. **"Three steps" in Simple mode** = off-centre, creep, zero drift (the three guided recordings). Temperature sensitivity is **not** a step: it is derived automatically when the calibration observations carry temperatures ≥ 2 K apart, or typed in a folded optional box ("Temperature (optional, not a step)"). Each step is optional; skipping = not recording.
2. **Mapping to the "not included" list:** off-centre loading → "off-centre loading", creep → "creep", zero drift → **"drift between calibration and use"** (the old list had no separate zero-drift entry), temperature → "temperature". Long-term drift over weeks is still unmodelled.
3. **Conversions (please confirm with the firmware):** `steinhart-hart`: raw = resistance in Ω, 1/T = a + b ln R + c (ln R)³ in K, result °C. `beta`: raw = resistance in Ω, `rSeries` (my assumption) is a resistance **in series with the NTC and is subtracted** (R_ntc = raw − rSeries), `t0` in °C. `polynomial`: c0 + c1 x + c2 x² …. A failed conversion is NaN (sample counted invalid, never 0); it also blocks interpolation.
4. **Temperature channels must deliver °C** (unit `°C`, `C` or `degC`); other units are rejected with a message. ΔT is always in K.
5. **Eccentricity:** deviation = (counts − centre counts) / slope at the test mass (fit slope, sign kept); fraction = largest |deviation| / test mass; half-width in the uncertainty = fraction × mass of the result, rectangular, **no extra ÷ 2** (as corrected in v14.1). Several recordings of one position are averaged. Default test weight in the wizard = the load nearest ⅓ of the heaviest.
6. **Creep:** fraction(t) = (r(t) − r(settle)) / (r(settle) − r_empty) at 30, 60, 120, 300, 600, 900, 1200, 1800 s (those that fit; t from the start of the recording; r = mean of series points within ±2 s). r_empty = mean of the **included empty-platform calibration observations** (record the empty platform first, otherwise creep is refused with a reason). The curve is 0 at the settle time and linear between stored points; beyond the last point its last value is used and the component note says so.
7. **Zero drift:** the recording is cut into ~20 block means (with SD and n); weighted straight-line fit with weights 1/se² (floor 0.2 × median se); rate and standard error in mg/h (SE = √(s²/Sxx), s² scaled by the residuals). Uncertainty half-width = √((rate·t)² + (se·t)²), t = `sessionSinceTareS`, then ÷ √3.
8. **Validity of creep / zero-drift recordings:** by design they drift, so only **gaps, range, vibration and a step that is step-like** can make them invalid (`charStatus`); autocorrelation, Allan and a trend are shown but ignored. **Limitation:** the step check reports "n/a" when the residuals are strongly correlated (strong drift), so a moved weight inside a strongly drifting recording may go undetected.
9. **Long recordings** (creep up to 30 min, zero drift up to 60 min) are collected while the samples arrive and are **independent of the ring buffer** (a 60 min recording at 80 Hz is 288,000 samples, more than the default 100,000 buffer and the 100,000 measurement limit). Limit `CHAR_MAX_SAMPLES` = 600,000. A tare, calibration change, sensor switch, gap or clearing cancels the recording (logged). Only the block means are stored in the file, not the samples.
10. **Temperature sensitivity from a sensor:** regression raw = a + a₁ΔT + b·x + b₂·x·ΔT over all included calibration observations (x = mass / scale, ΔT = T − mean T). Zero shift = a₁ / (b/scale) in mg/K, span = b₂/b in ppm/K; `referenceC` = mean temperature of the observations. Standard errors ignore the (small) uncertainty of b. Refused with a reason if fewer than `TEMP_FIT_MIN_POINTS` (5) observations carry a temperature, the range is below `TEMP_FIT_MIN_RANGE_K` (2 K), only one mass, or temperature varies together with mass. Typed values: "zero shift per 10 K" and "span ppm/K", source `user-estimate`. **Temperature correction of the readings is not done.**
11. **Temperature in the uncertainty:** ΔT = largest |T − referenceC| over the measurement, taken from the **primary** temperature channel of the shown sensor (selectable per cell; default = first attached) when a channel and a `referenceC` exist; otherwise the typed `temperatureDeltaK` (default 3 K). The label says "temperature your estimate" unless both the sensitivity and ΔT are measured.
12. **"Recorded under a different calibration revision" (v14.1 §7)** cannot be tested literally: the tests' raw counts do not depend on the active calibration and a file's own revision includes the block. Implemented as: each test stores `calibrationProfileId` (the profile whose fit converted it); if that differs from the profile in use, the component note says "converted with another calibration (profile …)". Each test observation also stores `recordedUnderRevision` for the record.
13. **Typed estimates** (Advanced tab only): eccentricity % of load, creep % after 1 min, zero drift mg/h, temperature as above; source `user-estimate`. Measured tests win over typed values. Status: `measured` = all four measured, `user-estimate` = everything present is typed, otherwise `partly measured`, nothing = `none`.
14. **Shared clock:** the device origin is claimed by the first accepted sample of any sensor or channel of that device; a sensor that joins later with earlier timestamps can get negative times (as already happens with merged history).
15. **Channels:** all shown channels of a sensor share one right-hand axis (unit of the first); default shown when attached, hidden per sensor with the toggle; the navigator does not show them. Channels are paused only with "Pause all" (no per-channel button yet).
16. **Use conditions** exist for every sensor including the test signal; the Sensor tab explains the effect in plain words (e.g. "creep after 30 s: ±x mg at half load").
17. `sensor_settings.json` additive keys: `sensors[].useConditions {readingDelayS, sessionSinceTareS, temperatureDeltaK, primaryTemperature}`, top-level `auxChannels:[{id, name, kind, conversion}]` (`conversion` = the user's correction, null = firmware). Loading the file applies both and reports unknown channels / invalid conversions.

## 3. File keys (all additive; `schemaVersion` stays 1)
- `calibration.json`: `characterization {status, profileId, eccentricity {testMassMg, centreRaw, positions[{name,raw,devMg}], maxAbsDevMg, fractionOfLoad, source, observationIds, calibrationProfileId}, creep {testMassMg, settleS, samples[{tS,fraction}], source, …}, zeroDrift {rateMgPerH, seMgPerH, durationS, source, …}, temperature {referenceC, zeroMgPerK, zeroSe, spanPpmPerK, spanSe, source, channelId, note, …}, overriddenObservations, notes}`; `observations[].purpose|position|series[{tS,raw,n,sd}]|settleS|temperatures{id:{mean,min,max,unit}}|recordedUnderRevision`. Old files without the block load and show "not characterized"; no number is invented.
- `ui-settings.json`: `tempRateWindowS` (5–3600, default 60).
- `sensors.json`: see §1. Example: `sensors_example_aux.json`.
- `checkweighings.json`: `{schemaVersion:1, calibrationRevisionId, entries:[{recordedAt, weightId|null, referenceMassMg, readingMg, sigmaMg|null, neff|null, temperatureC|null, note}]}`.

## 4. Server / firmware assumptions (to confirm)
- SSE sample of a channel: `{"id":"t-body","t":<device ms>,"raw":<float>,"n":<sample id>}` (float, not rounded). Channels and load cells of one device must use **the same clock** and the same `deviceId`.
- History API identical for channels (`sensor=<channel id>`). JSON `{samples:[{n,t,raw}]}` with float `raw`, or binary **layout v2**: `HIST` magic, u16 version **2**, u16 0, u32 count, count × (u32 id, u32 ms, **f64 raw**), little endian (v1 with 12-byte records still decodes).
- The ESP32 chip temperature is not used as load-cell temperature (decision 7).
- Open as before: how many samples the device keeps, maximum chunk size, CORS / `Authorization` for writes.
